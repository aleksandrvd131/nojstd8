# Карта UI-компонентов и интерфейсной архитектуры TuringIDE

Данный документ содержит детальный анализ архитектуры пользовательского интерфейса, иерархии компонентов, потоков данных, интеграции с библиотекой графов `@xyflow/react` (React Flow), механизмов синхронизации с лентой машины Тьюринга, специализированными редакторами (таблица четверок/пятерок, матрица переходов) и хранилищем Zustand.

---

## 1. Обзор архитектуры интерфейса (UI Architecture Overview)

Интерфейс **TuringIDE** спроектирован по принципу модульного **Single-Page Application (SPA)** в строгой **CAD / Linear-like** эстетике. Приложение оптимизировано для работы на лабораторных практикумах, академических исследованиях и промышленной визуализации алгоритмов автоматов.

### Ключевые архитектурные принципы:
1. **Full-Viewport CAD Layout**: Приложение занимает ровно `100vw × 100vh` с фиксированными зонами (Header, Canvas, Inspector, Docked Tape & Controls) и полным отсутствием неконтролируемого скролла страницы (`overflow-hidden`).
2. **Zero-Lag Двунаправленная синхронизация (Bi-directional Binding)**:
   - Изменения на визуальном холсте (добавление узлов, связывание ребер, редактирование условий) мгновенно транслируются в структуры правил (`rules5`, `rules4`) и отображаются в табличном редакторе (`TupleTableEditor`) и матрице переходов (`MatrixEditor`).
   - Изменения в таблицах или ячейках матрицы мгновенно порождают или перестраивают соответствующие узлы и ребра графа на холсте.
3. **Мультимодальность формализма**:
   - **5-кортежи (5-tuples)**: Классическая модель Тьюринга $(q, a, a', d, q')$.
   - **4-кортежи (4-tuples / Post-Turing)**: Модель с атомарными командами сдвига или записи $(q, a, C, q')$.
   - **Операционные диаграммы VTM**: Визуальные блок-схемы алгоритмов Тьюринга (узлы `START`, `FINISH`, сдвиги `l`/`r`, поиск `L`/`R`, запись `[a]`, вызов подмашин).
4. **Атомарная подписка Zustand**: Компоненты подписаны исключительно на необходимые срезы состояния (slices), что исключает лишние ре-рендеры холста при тактовой анимации ленты или таймера отладчика.
5. **Адаптивная темизация (Dark / Light)**: Глубокая поддержка светлой и темной тем на базе классов Tailwind (`dark`) и синхронизации с `@xyflow/react` через свойство `colorMode`.

## 3. Модуль холста диаграмм (`src/components/canvas/`)

### 3.1. `TuringCanvas.tsx`
- **Назначение**: Главный контейнер графового редактора на базе `@xyflow/react` v12.
- **Подключение провайдера**: Обернут в `<ReactFlowProvider>` (`TuringCanvas` экспортирует обертку над `TuringCanvasInner`), что гарантирует доступ к хуку `useReactFlow()` (`fitView`, зумирование и выравнивание).
- **Компоновка**:
  - **Плавающая панель инструментов (FAB Toolbar)**:
    - В режимах `5-tuple` и `4-tuple state-graph`: Кнопки добавления промежуточного состояния `+ Состояние` (`addStateNode('normal')`) и останова `+ Halt` (`addStateNode('halt')`).
    - В режиме `operational (VTM)`: Набор кнопок быстрого создания функциональных узлов: `START`, сдвиги `l`, `r`, поиск до пробела `L`, `R`, запись `[a]`, останов `FINISH`.
    - Кнопка **Раскладка** (`applyAutoLayout`): Вызывает библиотеку `dagre` для иерархического автоматического позиционирования графа слева направо (`rankdir: 'LR'`) с последующей анимацией центрирования `fitView({ duration: 300 })`.
  - **Интеграция с React Flow**:
    - `nodeTypes`: `{ stateNode: StateNode, operationNode: OperationNode }`.
    - `edgeTypes`: `{ customTransition: CustomTransitionEdge }`.
    - `defaultEdgeOptions`: Маркер стрелки `MarkerType.ArrowClosed` цвета `#71717a`.
    - Селекторы изменения графа: `onNodesChange`, `onEdgesChange`, `onConnect`.
    - Обработчики выделения: `onNodeClick`, `onEdgeClick`, `onPaneClick` — синхронизируют `selectedNodeId` и `selectedEdgeId`.
    - Миникарта `MiniMap` с кастомной палитрой узлов: начальные узлы — изумрудные (`#10b981`), узлы останова — янтарные (`#f59e0b`), промежуточные — серые (`#71717a`), операционные — индиго (`#6366f1`).

### 3.2. `StateNode.tsx`
- **Назначение**: Отрисовка состояний автомата $Q$ (классическая теория конечных автоматов и машин Тьюринга).
- **Типы состояний (`stateType`)**:
  - `initial` — стартовое состояние (иконка `Play`, акцент изумрудного цвета).
  - `normal` — промежуточное состояние.
  - `halt` — состояние останова (иконка `CircleDot`, янтарный цвет).
  - `accept` — допускающее состояние (иконка `CheckCircle2`, бирюзовый цвет).
  - `reject` — отвергающее состояние (иконка `XCircle`, коралловый цвет).
- **UX и оформление**:
  - **Двойная рамка**: Для терминальных состояний (`isFinal = halt | accept | reject`) применяется классическая двойная контурная обводка автоматов (`outline outline-1 outline-offset-2`).
  - **Точки подключения (Handles)**: 4 прецизионных порта (`top`, `right`, `bottom`, `left`) с миниатюрными контактными площадками, поддерживающими как `source`, так и `target`.
  - **Индикация активного шага**: При совпадении `runtime.currentNodeId === id` узел подсвечивается янтарным ореолом (`ring-1 ring-amber-500/40`) и помечается компактным моноширинным бейджем `ACT`.

### 3.3. `OperationNode.tsx`
- **Назначение**: Отрисовка функциональных блоков операционной блок-схемы (VTM, визуальные машины Тьюринга).
- **Поддерживаемые типы блоков (`opType`)**:
  | Тип операции | Код | Описание | Цвет бейджа |
  | :--- | :---: | :--- | :--- |
  | `START` | `.` | Точка входа в программу | Изумрудный |
  | `FINISH` | `HALT` | Точка останова машины | Розовый/Красный |
  | `SHIFT_L` | `l` | Сдвиг каретки влево на 1 шаг | Небесно-голубой |
  | `SHIFT_R` | `r` | Сдвиг каретки вправо на 1 шаг | Небесно-голубой |
  | `SEARCH_L` | `L` | Поиск символа влево до пробела | Индиго |
  | `SEARCH_R` | `R` | Поиск символа вправо до пробела | Индиго |
  | `WRITE_SYM` | `[a]` | Запись заданного символа на ленту | Фиолетовый |
  | `COMPLEX_MACHINE` | `K` | Вызов вложенной подмашины (подпрограммы) | Янтарный |
- **Индикация**: Отображает метку блока, пиктограмму типа, кодовый бейдж, а также индикатор активного выполнения `ACT`.

### 3.4. `CustomTransitionEdge.tsx`
- **Назначение**: Отрисовка дуг переходов между состояниями с поддержкой нескольких правил на одном ребре.
- **Геометрия путей**:
  1. **Петля самоперехода (`source === target`)**: Строится кубическая кривая Безье вверх над узлом с динамическим расчетом высоты (70px) и ширины (40px) петли.
  2. **Двунаправленные встречные переходы (`isBiDirectional`)**: Автоматически рассчитывается вектор нормали $(-dy/len, dx/len)$, смещающий кривую дуги на 36px вправо по направлению движения, что гарантирует идеальное визуальное разделение ребер $q_i \to q_j$ и $q_j \to q_i$ без перекрытий.
  3. **Стандартный переход**: Оптимизированная кривая `getBezierPath`.
- **Интерактивные шильдики правил (`EdgeLabelRenderer`)**:
  - Каждое ребро может нести коллекцию правил `rules: EdgeRuleItem[]`.
  - Форматирование метки в зависимости от режима:
    - 5-tuple: `0 → 1, R`
    - 4-tuple граф: `0 : R` или `0 : 1`
    - 4-tuple VTM: `0`, `*` (любой символ / wildcard)
  - Клик по пиллу открывает модальное окно редактирования `RuleModal`.
  - Кнопка удаления правила `X` появляется при наведении.
  - Кнопка `+` позволяет добавить альтернативную ветку перехода по тому же направлению.
  - Активное ребро при выполнении (`runtime.activeEdgeId === id`) подсвечивается янтарным цветом, утолщается и становится пунктирным (`strokeDasharray: '5 4'`).

### 3.5. `NodeInspector.tsx`
- **Назначение**: Контекстная плавающая панель свойств выбранного узла (`selectedNodeId`).
- **Функциональность**:
  - Быстрое закрытие по клавише `Escape` или крестику.
  - Кнопка полного удаления узла и всех инцидентных ему ребер и правил (`deleteNode`).
  - Редактирование метки/имени узла (`label`).
  - Для состояний: смена типа состояния (`normal`, `initial`, `halt`, `accept`, `reject`), ввод текстового описания/примечания.
  - Для операций: смена типа операции, выбор записываемого символа из алфавита (для `WRITE_SYM`), выбор вызываемой подмашины из списка `subMachines` (для `COMPLEX_MACHINE`).

### 3.6. `RuleModal.tsx`
- **Назначение**: Центрированное модальное окно добавления или редактирования правила перехода.
- **Интерфейс адаптивен к режиму машины**:
  - **5-кортежи**: Выбор считываемого символа ($a$), выбор записываемого символа ($a'$), выбор сдвига каретки кнопками `← L`, `• N`, `→ R`.
  - **4-кортежи**: Переключатель характера команды (сдвиг каретки `L`/`R`/`N` или запись символа на ленту).
  - **Операционные диаграммы**: Чекбокс символа-джокера (`*` — любой символ) или выбор конкретного символа ветвления.
- **Действия**: Сохранение (создает или обновляет правило в Zustand), удаление текущего правила, закрытие.

## 4. Модуль ленты и отладчика (`src/components/tape/`)

### 4.1. `InfiniteTapeDock.tsx`
- **Назначение**: Интерактивная модель потенциально бесконечной в обе стороны ленты машины Тьюринга.
- **Модель данных**: Разреженный массив `SparseTape: Record<number, string>`. Неинициализированные ячейки неявно считаются содержащими `blankSymbol` ($\lambda, \_, \sqcup, a_0$).
- **Компоненты дока**:
  1. **Поле быстрой загрузки слова**: Форма ввода строки (напр., `10110`), которая раскладывается на ленту с индекса 0 вызовом `setTapeString(inputWord, 0)`.
  2. **Координатор головки (HEAD Tracker)**: Моноширинный индикатор позиции с иконкой `Crosshair`.
  3. **Управление буфером (Snapshots)**:
     - `В буфер` (`saveTapeToInitialBuffer`): Фиксирует текущее состояние ленты и позицию головки как исходные данные задачи.
     - `Сброс ленты` (`resetTapeFromInitialBuffer`): Мгновенно возвращает ленту к зафиксированному буферу.
  4. **Навигация**: Кнопки прокрутки ленты влево/вправо с шагом $\pm 5$ ячеек (`rangeOffset`). Автоматическое центрирование видимой области при движении головки.
  5. **Прецизионная линейка ячеек (CAD Precision Strip)**:
     - Окно отображения из 25 ячеек, центрированное вокруг головки.
     - Указатель головки: четкий янтарный треугольный нотч без прыгающих анимаций.
     - Индивидуальная ячейка:
       - Подсветка текущей ячейки головки (янтарный фон, жирный шрифт).
       - Подсветка ранее посещенных ячеек (`isVisited = runtime.visitedPositions.includes(pos)`).
       - Индекс координаты ячейки под коробкой (поддерживаются отрицательные индексы $\dots, -2, -1, 0, 1, 2, \dots$).
       - Клик по ячейке переносит головку в эту позицию и активирует инлайн-редактирование символа через выпадающий список.

### 4.2. `DebuggerControls.tsx`
- **Назначение**: Панель воспроизведения, тактовой отладки и технического мониторинга исполнения алгоритма.
- **Элементы управления**:
  - `Сброс [Esc]` (`resetExecution`): Возврат машины в исходное состояние $q_0$, восстановление исходной ленты и очистка истории.
  - `Шаг назад [←]` (`stepBack`): Пошаговый реверс исполнения на основе стека снимков `runtime.history` (доступен, если `history.length > 0`).
  - `Запуск / Пауза [R]` (`startRunning` / `pauseRunning`): Непрерывное автоматическое выполнение программы по таймеру `setInterval`. При переходе в `halted` или `error` автоматически ставится на паузу.
  - `Шаг вперед [Space / →]` (`stepForward`): Одиночный такт работы машины Тьюринга.
  - **Ползунок скорости (Speed Slider)**: Регулировка интервала шага от 30 мс (максимальная скорость) до 800 мс (замедленный пошаговый просмотр).
- **Информационное табло статуса**:
  - Цветовой светодиодный индикатор статуса:
    - `running` — пульсирующий голубой
    - `halted` — зеленый (успешный останов)
    - `error` — красный (ошибка)
    - `idle` / `paused` — нейтральный серый
  - Моноширинный текст текущего состояния отладчика (`runtime.statusMessage`).
- **Технические телеметрические счетчики**:
  - `STACK`: Глубина стека вызовов подмашин (`runtime.callStack.length`).
  - `TICK`: Общее количество выполненных тактов/шагов (`runtime.stepCount`).
  - `CELLS`: Количество уникальных ячеек ленты, затронутых головкой (`runtime.visitedPositions.length`).

### 4.3. `BatchTestRunner.tsx`
- **Назначение**: Пакетный прогон набора тестовых примеров (Unit-тестирование машины Тьюринга).
- **Возможности**:
  - Добавление именованных тестов: Входное слово (`inputTape`), Ожидаемое слово (`expectedTape`), Ожидаемый останов (`expectedHalt`).
  - Запуск всех тестов в пакетном режиме (`runAllTestCases`).
  - Одиночный запуск теста (`runSingleTestCase`).
  - Загрузка теста на основную ленту холста (`handleLoadToMainTape`).
  - Визуальная индикация: Зеленый `CheckCircle2` (Passed), Красный `XCircle` (Failed), количество шагов выполнения (`lastStepsCount`).
  - Статистика: отображение числа успешно пройденных тестов из общего количества.

## 5. Модуль инспекторов и редакторов (`src/components/inspector/`)

Панель инспектора располагается справа (`w-96 lg:w-[420px]`) и переключается между 4 вкладками:

### 5.1. `TupleTableEditor.tsx` (Таблица правил)
- **Назначение**: Табличное представление системы команд машины Тьюринга.
- **Режимы отображения**:
  - **5-кортежи**: Колонки $[q, a, a', d, q']$ (Исходное состояние, Чтение, Запись, Сдвиг $L/R/N$, Следующее состояние).
  - **4-кортежи (граф)**: Колонки $[q, a, C, q']$ (Исходное состояние, Чтение, Команда сдвига или записи, Следующее состояние).
  - **4-кортежи (VTM)**: Показывает заглушку Empty State с пояснением, что в операционном режиме блок-схем правила определяются связями между функциональными узлами.
- **Интерактивность**:
  - Все ячейки таблицы являются инлайн-селекторами или полями ввода. Изменение любого параметра немедленно обновляет структуры в Zustand и синхронизирует ребра/метки на холсте.
  - Подсветка активного правила: Правило, выполняемое на текущем такте отладки (`runtime.activeRuleId === r.id`), подсвечивается янтарным фоном и жирным шрифтом.
  - Быстрое удаление правила кнопкой корзины `Trash2`.
  - Форма быстрого добавления нового кортежа внизу таблицы.

### 5.2. `MatrixEditor.tsx` (Матрица переходов $A \times Q$)
- **Назначение**: Каноническая матрица переходов теории автоматов, где строки соответствуют символам внешнего алфавита ленты $A$, а столбцы — состояниям автомата $Q$.
- **Особенности и возможности**:
  - Строки: Все рабочие символы алфавита плюс пустой символ `blankSymbol`.
  - Столбцы: Все состояния $q_i \in Q$. Текущее состояние машины при отладке подсвечивается янтарной шапкой.
  - Содержимое ячейки $(a, q)$:
    - Пустая ячейка: `—`.
    - Детерминированный переход: отображение команды (напр., `1, R, q1`).
    - **Недетерминированный переход**: Если для одной пары $(q, a)$ существует более одной команды, ячейка отображает бейдж `Недетерм. (N)` и список альтернатив через разделитель `|`. Всплывающий тултип детально перечисляет все ветки.
  - Клик по ячейке: Открывает нижнюю панель быстрого редактирования или добавления новой ветки перехода.
  - Индикация активной ячейки: Ячейка, соответствующая текущей комбинации $(q_{curr}, a_{curr})$, динамически подсвечивается.

### 5.3. `DiagnosticsPanel.tsx` (Статический анализатор / Check)
- **Назначение**: Автоматическая проверка корректности и семантических инвариантов машины Тьюринга в реальном времени.
- **Под капотом**: Вызывает функцию `validateMachine(session)` из `src/engine/validator.ts`.
- **Классификация диагностик**:
  - **Ошибки (`error`)**:
    - Отсутствие начального состояния (`initial state` / `START`).
    - Несколько начальных состояний.
    - Дублирование символа в алфавите или совпадение рабочего символа с пустым символом `blank`.
    - Использование зарезервированных символов (`L`, `R`, `N`, `<`, `>`, `.`).
    - Недетерминизм (конфликтующие правила для одной пары состояние/символ).
    - Переходы в несуществующие состояния.
  - **Предупреждения (`warning`)**:
    - Отсутствие терминального состояния (`halt`, `accept`, `reject` или `FINISH`).
    - Изолированные недостижимые состояния.
    - Отсутствие исходящих переходов из нетерминальных состояний.
  - **Информационные сообщения (`info`)**:
    - Рекомендации по оптимизации и полноте алфавита.
- **Интерактивная навигация**: Клик по любой диагностической карточке центрирует и выделяет на холсте ассоциированный узел (`nodeId`) или ребро (`edgeId`).

- **Возможности**:

    - Бинарный (`0, 1, _`)
    - Унарный с маркерами (`1, *, x, =, _`)
    - Десятичный (`0–9, _`)
    - Шестнадцатеричный (`0–F, _`)

  - **Атомарный рефакторинг символа (`refactorSymbol`)**: При переименовании символа в алфавите (например, `1` в `X`) движок автоматически производит сквозную замену этого символа во всех правилах переходов (`rules5`, `rules4`), условиях ребер графа, на ячейках ленты и в тестовых наборах.

### 6.3. `SessionManagerDrawer.tsx`
- **Назначение**: Боковой дровер управления проектами и демонстрационными примерами.
- **Хранение данных**: Автосохранение в `localStorage` через безопасную обертку `safeStorage` (с fallback на `Map` в памяти).
- **Функционал**:
  - Поиск проектов по названию и описанию.
  - Переключение между проектами (`switchProject`).
  - Создание нового проекта с выбором математического режима.
  - Дублирование существующих проектов (`duplicateProject`).
  - Экспорт отдельного проекта в `.json`.
  - Импорт проекта из локального `.json` файла через `FileReader`.
  - Удаление проекта (с защитой от удаления последнего проекта).

### 6.4. `ExportModal.tsx`
- **Назначение**: Центр экспорта машины Тьюринга в академические форматы и графические отчеты.
- **Поддерживаемые форматы**:
  1. **JSON**: Полная сериализация проекта (узлы, геометрия, правила, алфавит, начальная лента, тест-кейсы).
  2. **LaTeX**: Готовый компилируемый документ `article` с таблицей переходов, определением алфавита и состояний для вставки в отчеты по лабораторным работам.
  3. **PlantUML**: Диаграмма состояний `@startuml ... @enduml` для автоматической генерации векторных схем переходов.
  4. **Markdown**: Полная текстовая спецификация алгоритма с таблицами в формате GitHub Flavored Markdown.
  5. **Снимок (PNG / SVG)**: Графический экспорт графа холста без интерфейсных панелей.

## 8. Поток данных и селекторы Zustand (`src/store/useTuringStore.ts`)

### 8.1. Структура глобального состояния (`TuringStoreState`)

```typescript
interface TuringStoreState {
  projects: ProjectSession[];          // Коллекция всех сохраненных машин
  activeProjectId: string;             // Идентификатор текущей машины
  runtime: RuntimeState;               // Динамическое состояние исполнения отладчика

  // Состояние интерфейса
  theme: 'light' | 'dark';             // Цветовая тема
  activeTab: 'tuples' | 'matrix' | 'check' | 'tests'; // Активная вкладка инспектора
  selectedNodeId: string | null;       // Выбранный узел холста
  selectedEdgeId: string | null;       // Выбранное ребро холста
  isSessionDrawerOpen: boolean;        // Дровер сессий
  isAlphabetModalOpen: boolean;        // Модалка алфавита
  isExportModalOpen: boolean;          // Модалка экспорта
  isRuleModalOpen: boolean;            // Модалка правила ребра
  ruleModalData: { ... } | null;       // Контекст открытого правила
  executionSpeedMs: number;            // Скорость отладчика (мс)
  isRunning: boolean;                  // Флаг непрерывного автовыполнения
  keyboardShortcutsEnabled: boolean;   // Флаг активности горячих клавиш

  // Экшены управления проектами, графом, алфавитом, лентой, отладчиком и тестами...
}
```

### 8.2. Специализированные хуки и селекторы
- `useActiveProject()`: Селектор, возвращающий объект активной сессии `ProjectSession`. Предотвращает циклические вызовы и гарантирует fallback на дефолтный проект при переключениях.
- `useRuntimeStats()`: Вычисляет производные телеметрические метрики в реальном времени (`stepCount`, `headPosition`, `minTapeIndex`, `maxTapeIndex`, `tapeSpan`, `nonBlankCellsCount`, `visitedPositionsCount`, `callStackDepth`).
- `useKeyboardShortcuts()`: Хук глобальной подписки на события клавиатуры окна браузера `window.addEventListener('keydown')`.

## 9. Горячие клавиши и UX-поведение (Hotkeys & UX Interactions)

### 9.1. Таблица сочетаний клавиш

| Клавиша | Контекст | Действие | Метод в Store |
| :--- | :--- | :--- | :--- |
| **`Space`** | Глобальный | Одиночный такт вперед | `stepForward()` |
| **`Shift + Space`** | Глобальный | Одиночный такт назад (реверс) | `stepBack()` |
| **`→` (ArrowRight)** | Глобальный | Шаг вперед по тактам | `stepForward()` |
| **`←` (ArrowLeft)** | Глобальный | Шаг назад по тактам | `stepBack()` |
| **`R`** | Глобальный | Переключение Запуск / Пауза | `toggleRunning()` |
| **`Escape`** | Глобальный | Сброс машины в начальное состояние | `resetExecution()` |
| **`Escape`** | NodeInspector | Закрытие панели свойств узла | `setSelectedNodeId(null)` |
| **`Escape`** | RuleModal | Закрытие модального окна правил | `closeRuleModal()` |

### 9.2. UX-защита ввода (Focus Safety)
- В обработчике `handleDebuggerKeyboardShortcut` реализована строгая проверка: если фокус ввода находится в тегах `<input>`, `<textarea>`, `<select>` или элементах с `isContentEditable`, глобальные горячие клавиши отладчика (пробел, стрелки, R, Esc) **автоматически игнорируются**, предотвращая случайный сброс или запуск автомата во время набора текста.

### 9.3. UX-интерактивность графа
- **Клик по узлу**: Фокусирует узел, снимает выделение с ребер, открывает плавающий инспектор свойств `NodeInspector`.
- **Клик по свободному месту холста (`onPaneClick`)**: Сбрасывает выделение узлов и ребер, закрывает плавающие панели.
- **Клик по пиллу перехода на ребре**: Открывает модалку `RuleModal` именно для выбранного правила.
- **Перетаскивание узлов (`nodesDraggable`)**: Свободное позиционирование узлов с персистентным сохранением координат в Zustand через `onNodesChange`.
- **Соединение узлов (`onConnect`)**: Перетаскивание стрелки между портами узлов автоматически открывает `RuleModal` с предзаполненными `sourceNodeId` и `targetNodeId`.
