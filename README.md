# nojstd — интерактивный редактор и симулятор машин Тьюринга

Современная веб-среда (SPA) для моделирования, визуализации и отладки классических и операционных машин Тьюринга. Приложение разработано на базе React 18, TypeScript, `@xyflow/react` (React Flow v12), Zustand и TailwindCSS.

---

## 🌟 Ключевые возможности

### 1. Модели машины
- Движок поддерживает два формата правил и операционные диаграммы; текущий интерфейс ориентирован на редактирование операционных диаграмм VTM. Проекты других режимов также поддерживаются движком и форматом проекта.
- **Режим в пятёрках (5-tuple mode)**:
  - Формат перехода: $(q, a, a', d, q')$, где $d \in \{L, R, N\}$. За один такт машина одновременно перезаписывает символ и сдвигает головку.
  - Визуализация в виде графа состояний ($q_0, q_1, \dots$), начальное состояние и состояния останова (Halt / Accept / Reject).
- **Режим в четвёрках (4-tuple mode)**:
  - Формат перехода: $(q, a, C, q')$, где $C \in \Sigma \cup \{L, R, N\}$. За один такт машина либо выполняет сдвиг, либо записывает символ.
  - **Два синхронизированных подрежима**:
    1. *Граф состояний в четвёрках*: узлы — состояния, метки дуг — `read : command`.
    2. *Операционная диаграмма Тьюринга (в стиле VTM)*: академический стандарт курсов теории алгоритмов. Узлами выступают элементарные операции машины (`START`, `FINISH`, сдвиги `l` и `r`, поиск до пустого `L` и `R`, запись `[a]`, вложенные подмашины), а рёбра содержат условия ветвления по считанному символу (`a`, `*`, `¬a`).
- **Двусторонний автоматический транспилятор**:
  - Конвертация $5\text{-tuple} \leftrightarrow 4\text{-tuple}$ с автоматическим расщеплением совмещённых шагов через генерацию вспомогательных состояний $q_{\text{aux}}$.
  - Автоматическая компиляция операционной диаграммы VTM в каноническую таблицу четвёрок.

### 2. Специализированный движок графов на `@xyflow/react`
- **Группировка параллельных правил (Multi-Rule Edge Bundling)**: правила между состояниями объединяются в одно ребро и рендерятся в виде интерактивных плашек с перетаскиваемым смещением (`labelOffset`).
- **Интеллектуальные порты и ортогональная трассировка дуг**: автоматический выбор портов (`ports.ts`) и раскладка проводов (`wireLayout.ts`) с обходом узлов и разведением встречных переходов.
- **Кастомные петли (`CustomTransitionEdge`)**: замкнутые петли переходов узла в самого себя с адаптацией под сторону порта.
- **Автоматическая укладка графа**: интеграция с библиотекой `dagre` (`autoLayout.ts`) для упорядочивания вершин с защитой от наложения карточек.
- **Инспектор узла (`NodeInspector`) и Undo/Redo**: редактирование меток, типов состояний, операций и подмашин, массовое выделение/удаление и горячие клавиши (`useKeyboardShortcuts`).

### 3. Менеджер алфавитов и живой рефакторинг
- Готовые пресеты: Бинарный (`0, 1`), Унарный с маркерами (`1, *, x, =`), Десятичный (`0–9`), Шестнадцатеричный (`0–9, A–F`), Символьно-логический (`#, $, 1, 0, T, F`).
- Конструктор произвольных пользовательских символов.
- Выбор отображения пустого символа: `_`, `λ`, `␣`, `a0`.
- **Живой рефакторинг (Live Refactoring)**: при переименовании символа в алфавите он автоматически обновляется во всех правилах переходов, на холсте, в таблицах и на ленте.

### 4. Редактирование и проверка
- Редактор графа позволяет создавать узлы и переходы, редактировать правила и свойства узлов. Для операционных диаграмм доступен также ввод VTM-кода.
- Панель **Check** показывает результаты статического анализа: ошибки и предупреждения о начальных и конечных узлах, детерминированности, достижимости и других свойствах машины.
- Панель **Тесты** предназначена для пакетного запуска тестовых случаев.

### 5. Бесконечная лента и пошаговый отладчик
- Двусторонне-бесконечная разреженная лента (`Record<number, string>`) с интерактивным редактированием ячеек и строковым вводом слова.
- Буфер начального состояния (сохранение в буфер и сброс ленты).
- Управление исполнением: шаг вперёд и назад по истории снимков, запуск и пауза с регулированием скорости (от 30 до 800 мс), а также быстрый запуск.
- Метрики вычислительной сложности:
  - **Временная сложность**: количество выполненных тактов.
  - **Пространственная сложность**: количество задействованных ячеек ленты.
- Пакетное тестирование: проверка результирующей ленты, позиции головки и типа останова по заданным ожиданиям.

### 6. Персистентность сессий и модуль экспорта
- Автосохранение всех сессий в `localStorage` браузера через Zustand persist.
- Боковая панель менеджера проектов: поиск, дублирование, удаление, текстовое поле для формулировки условия задачи.
- Экспорт в форматы:
  - **JSON** (полный дамп проекта и импорт);
  - **LaTeX** (формальное определение $M = \langle Q, \Sigma, \Gamma, \delta, q_0, B, F \rangle$ и таблицы переходов с экранированием спецсимволов) и **TikZ** (`exportToTikZ`);
  - **PlantUML** (спецификация диаграммы состояний);
  - **Markdown** (таблицы в формате GitHub Flavored Markdown);
  - **PNG / SVG** — графический снимок холста через интерфейс экспорта.

## ⚠️ Ограничения модели (By Design)

- **Одноленточная архитектура**: проект моделирует классическую машину Тьюринга с одной двусторонне-бесконечной разреженной лентой (`SparseTape`). Многоленточные машины не поддерживаются.
- **Детерминированная симуляция**: исполнитель (`simulator.ts`) выбирает первый подходящий переход. Недетерминированные правила выявляются статическим анализатором (`validator.ts`); многоветвевой поиск (NTM BFS/DFS) не реализован.
- **Обнаружение зацикливания**: используется скользящее окно последних 256 конфигураций (`MAX_CYCLE_WINDOW = 256`), поэтому оно не обнаруживает все возможные циклы. Пакетный и быстрый запуск по умолчанию ограничены 10 000 шагов.

## 🚀 Установка и запуск

```bash
# Перейдите в каталог клонированного репозитория
cd nojstd8

# Установка зависимостей
npm install

# Запуск локального сервера разработки
npm run dev

# Запуск тестов движка, стора и компонентов
npm test

# Проверка типов
npm run typecheck

# Сборка оптимизированного production-бандла
npm run build

# Предпросмотр production-сборки
npm run preview

# Проверка типов, тесты и сборка
npm run check
```

Для интерактивного запуска тестов используйте `npm run test:watch`. Команда `npm run check:graph` проверяет актуальность артефактов Graphify относительно отслеживаемых файлов проекта; обновление README или кода может потребовать обновления графа.
